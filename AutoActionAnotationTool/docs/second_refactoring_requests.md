## 現在のアーキテクチャの問題点

1. STTDataControllerとResultsDataControllerでアノテーションデータが2重管理されてしまっている。
    - stt 形式は最終的にエクスポートするときのデータ構造、moment-detr形式は前段の自動検出スクリプトとのインターフェースおよび編集中のアノテーションデータのデータ形式、という役割分担にしたい。
2. データ管理用のクラスが多く存在してしまっている。重複管理が発生しないように整理したい。
3. Step用のIntervalデータとAction用のIntervalデータの見分け方が良くない。query_textの頭の文字列比較で行っている。
4. ActionEditor,ActionEditCommandと、StepEditor,StepEditCommandの処理が似ているので、統一したい。Action用のデータとStep用のデータは同じデータクラスを使い、中の属性値で見分けるようにしたい。
5. 以上の問題を行ったうえで、使用しなくなったクラスの実装は削除したい。

## リファクタリング案を提案するうえでの思慮事項

1. 現状のクラス構成は維持しようとしなくてよい。後方互換性は取らなくてよい。
2. 現状のクラス名や変数名も維持しようとしなくてよいので、新しいアーキテクチャ上の役割にふさわしい名前を付けること。
3. エラーハンドリングは最小限で良い。存在することを前提とした変数を使う場合はいちいち存在チェックを行う必要はない。
4. むしろデバッグしやすいようにエラーが出るようにすること。デバッグしやすいようにログを多めに仕込むこと。
5. **重要** ただし、現状の機能は一切損なうことなく、現状の仕様を正として、デグレすることのないようにすること。
6. **重要** リファクタリング案がまとまったら、最後に現状の実装と照らし合わせて機能が変化してないか？失われた機能はないか？確認すること。

## リファクタリング案の出力方式

1. クラス図をmermaid記法で出力すること。
2. 出力する際は人間がチャット上でmermaid記法の文章をコピーできるように、チャット上でプレビューが行われないように出力すること。
3. クラス図には必要な変数や関数名（引数付）を全て列挙すること。
